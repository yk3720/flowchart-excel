## 1. 目的

Excel で表を直しながらフローを確認し、問題なければ AutoShape を作成する本線を、**1つの操作画面**で迷わず完結させる。

成功の定義（一期）:

- Excel クリック後もプレビューが作業継続できる（背面化で「消えた」と感じない）
- 前面の操作が **表読込 → プレビュー確認 → Excelに作成** に絞られている
- 作成内容が、直前に見ていたプレビューと一致する（または不一致時に作成を止める）

---

## 2. 現状の課題（As-Is）

| # | 課題 |
|---|------|
| 1 | プレビューが別プロセス WebView のため、Excel フォーカスで背面に回りやすい |
| 2 | 操作パネル（CTk）とプレビューが分離し、認知・操作が分裂 |
| 3 | 「選択範囲」「表全体」など本線以外の CTA が前面にある |
| 4 | スマートパレットが表駆動本線と別タスクなのに前面にある |
| 5 | 雛形・大中小など低頻度操作が前面を占有 |

---

## 3. 一期スコープ（To-Be）

### 3-1. やること

1. **1窓化（体験）** — 操作とプレビューを同一アプリ窓のレイアウトで扱う  
2. **Excel 作業中もプレビューが継続利用できる**（手段は調査書のルート A/B/C）  
3. **前面 CTA の一本化** — 本線のみ  
4. **選択範囲 CTA・スマートパレットを前面から除去**  
5. **雛形・サイズプリセット（大中小）・詳細寸法をメニューへ退避**  
6. **表示中プレビューと Excel 作成の一致契約**（スナップショットまたは fingerprint）

### 3-2. やらないこと（一期）

- flowchart-studio 編集機能の移植・双方向同期の拡張  
- スマートパレット代替 UI の新設  
- 文言・ビジュアルの全面リライト（必要最小限のラベルのみ）  
- 列 SSOT / AutoShape 出力仕様の変更  
- 新出力形式・共同編集など別機能  

### 3-3. 選択範囲の扱い（合意）

| 項目 | 決定 |
|------|------|
| 前面 | **出さない**（「選択範囲を確認して作成」削除） |
| 逃げ道 | **メニュー（または設定内）に退避**を一期推奨。完全削除は二期判断可 |
| 既定 | 表全体（`CurrentRegion`） |

## 4. 画面構成（情報アーキテクチャ）

```
┌──────────────────────────────────────────────────┐
│ Flowchart Excel     [設定 ▾]  [その他 ▾]          │
├──────────────────────────────────────────────────┤
│ ステータス: ブック / シート / 範囲 / ライブ ON·OFF │
│ [表を読み込んでプレビュー]   ← 作成ではない        │
├──────────────────────────────────────────────────┤
│                                                  │
│           React Flow プレビュー領域               │
│           （ライブ更新 · studio 同等描画）         │
│           未読込時: 「プレビューはまだありません」 │
│                                                  │
├──────────────────────────────────────────────────┤
│              [キャンセル]  [Excelに作成]          │
└──────────────────────────────────────────────────┘
```

### 4-1. 前面に残すもの

| 要素 | 役割 |
|------|------|
| ステータス | 対象ブック・シート・範囲モード・ライブ状態 |
| **表を読み込んでプレビュー** | 監視対象の確定 + プレビュー開始／再読込（**作成を含意しない**）。白＝対象未検出／青＝対象検出・未読込／緑＝プレビュー中の3状態色（§6契約表参照） |
| プレビュー領域 | studio 同等 React Flow + ライブ更新。未読込時は空状態文言を表示（§6契約表参照） |
| **キャンセル** | プレビュー中断（無効時は灰色固定） |
| **Excelに作成** | 表示中内容で AutoShape 描画（ゲート付き）。無効＝灰／有効＝青の2状態色（§6契約表参照） |

### 4-2. 設定 ▾ に退避

- 高さ・幅・行間・列間  
- 大 / 中 / 小  
- テーマ  

変更は可能ならプレビューへ即反映。

### 4-3. その他 ▾ に退避

- 雛形作成（初回・表未検出時は空状態 CTA として一時前面化してよい）  
- Undo（**作成直後はステータス／トーストで優先表示**を推奨）  
- 図面クリア（確認ダイアログ必須 · Undo と視覚分離）  
- ヘルプ  
- （任意）選択範囲モード  
- （任意）単体図形＝旧スマートパレット · 「プレビュー対象外」明示  

---

## 5. 操作フロー

1. Excel で表を用意（または雛形はメニューから）  
2. 本アプリで **表を読み込んでプレビュー**  
3. Excel 側で表を編集 → プレビューがライブ追従（編集中セルはスキップ可）  
4. 問題なければ **Excelに作成**  
5. 必要なら Undo  

---

## 6. 非機能・契約

| 項目 | 要件 |
|------|------|
| プレビュー品質 | flowchart-studio の `generateFlowchart` → `toReactFlow` → `FlowCanvas` 相当を維持 |
| ライブ更新 | 既存の約 0.75s ポーリング方針を維持（統合時はステータスポーリングと一本化検討） |
| 作成ゲート | 有効プレビューが無い／エラー時は「Excelに作成」無効。`nodeCount>0` かつ `validation_ok is True` の両方を要求（Phase 1b(a)、下記「作成可否のJS→Python通知」参照） |
| 一致契約 | 作成時は表示 fingerprint を凍結検証、または確定瞬間の表スナップショットで描画 |
| 「表を読み込んでプレビュー」ボタンの状態色 | 白＝対象未検出（押せる）／青＝対象検出・未読込／緑＝プレビュー中の3状態。`_update_preview_button_color()` が1秒間隔のExcel監視ポーリング（`_refresh_status_line`）に統合して判定 |
| 「Excelに作成」ボタンの状態色 | 無効時 `STYLE_SECONDARY`（灰）／有効時 `STYLE_PRIMARY`（青）の2状態。有効条件は上記「作成ゲート」参照 |
| 描画位置のアンカー | 「表全体」モードで外枠+タイトルを付ける際、選択セル＝外枠の外側の角に一致させる。`frame_anchor_offset()` が `FRAME_MARGIN`（30pt）+ `TITLE_GAP_ABOVE_SHAPE`（75pt）分だけ図形群の原点をオフセット（ADR-017） |
| フロータイトルの背景色 | タイトルのテキストボックスにのみ `FLOW_SURFACE_SUBTLE`（淡色グレー）を敷く。外枠自体は白のまま |
| プレビュー空状態 | 見出し「プレビューはまだありません」＋補足「Excelで表を選んだ状態で、上のボタンを押すとここに表示されます」（選択済み・未選択のどちらとも矛盾しない説明形） |
| 作成可否のJS→Python通知（埋め込み1窓） | 埋め込みWebViewは `webview.start()` を経由せず `window.pywebview.api` のpush通知（`.expose()`）が機能しないため、React側が `window.__flowchartValidation` に判定結果を書き込み、Python側が `core.ExecuteScriptAsync(...).ContinueWith(...)` で非同期ポーリングして取得する方式（`_poll_validation`/`_on_validation_js_result`）。2026-09-17 実機で正常系/異常系とも判定が正しく動くことを確認済み |
| 製品約束の文言 | 「常時 OS 最前面」絶対約束ではなく、**「Excel 操作中もプレビューが作業継続できる」**をゴールとする |
| 1窓の前面維持（手段） | メイン CTk に `attributes('-topmost', True)`（2窓フォールバック時は子 WebView `on_top`）。絶対最前面の製品約束ではない |
| 1窓の初期ジオメトリ | 縦長フロー向け **約 370×820**（旧 1100 幅の約 1/3 · 高さは維持）。最小はそれよりやや小さく可 |
